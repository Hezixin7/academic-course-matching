# 求职项目定位与简历

本版已经包含 LLM 应用的实际代码链路：语义召回、模型结构化判定、证据出处校验、失败处理、缓存和 trace，以及与模型解耦的业务计算。它可以作为继续完善的 LLM 应用开发作品集项目。

展示前先配置自己的密钥，完成真实模型验收并理解关键代码。当前自动测试使用测试模型响应，不能声称已经验证了真实 LLM 的判定效果。

## 可按实际参与情况改写

**Academic Course Matching Copilot｜基于 LLM 的可解释课程匹配系统**

技术栈：JavaScript / Node.js / Transformers.js / ONNX Runtime / Chat Completions API / Web Worker

- 实现课程描述 embedding 召回与 LLM 成对判定的两阶段流程，将课程与目标录取模块关联，输出匹配、部分匹配、不匹配和证据不足等结构化结果。
- 设计严格输出契约与原文引用校验，拦截错误编号、非法字段和伪造引用；将调用失败或证据不足的结果隔离至人工复核，避免直接进入学分分配。
- 将模型判定与学分核算解耦，通过课程级预算约束支持多对多分配及人工调整；编辑后确定性重算，不重新调用模型。
- 实现输入哈希缓存、超时重试与 Prompt/usage/耗时记录，建立检索基线对比和分类评测框架，并覆盖核心交互与异常路径测试。

这些表述描述现有实现。在自己理解和参与设计、修改、验收后使用，面试时说明 AI 辅助开发的范围，以及你独立做出的取舍和验证。

## 当前不能量化宣传

- 没有真实院校数据上的准确率、匹配成功率或成本下降百分比。
- 合成数据 Recall@3 只用于小样例回归；关键词基线同样达到很高分，不能据此宣称 embedding 优于所有基线。
- 没有真实 LLM 分类分数。需要自己的密钥跑出结果，再保留模型版本、数据划分与错误样例。
- 不应声称训练/量化模型、构建多智能体、实现官方 ECTS 认证，或保证录取。

## 接下来最有价值的自主工作

1. 真实模型验收，记录成功和失败例子；解释结构化 JSON 与语义正确性之间的区别。
2. 用合法公开材料或经授权的课程描述补真实标签，由另一位标注者复核一部分，记录分歧。保持开发/测试课程分离。
3. 比较名称检索、描述检索、关键词基线和召回后 LLM 判定；报告 Recall@k、Macro-F1、错误类型与有效引用率。
4. 检查否定表达、相同名称不同课程深度、部分覆盖、跨语言描述和提示注入文本。
5. 用实际测量决定是否增加批处理、并发或更换模型；性能数据要区分缓存命中与未命中。

## 面试时能展开的设计点

- 为什么先召回而不是把全部模块逐对交给 LLM？漏召回会如何限制下游分类？
- 为什么引用校验通过仍可能判断错误？如何用标签评测补足？
- 为什么多个完整匹配和部分匹配初始为 0，而不是按相似度分配学分？
- 模型和 Prompt 变更如何影响缓存？为什么缓存不等同于授权？
- 429、401、超时、截断和无效 JSON 分别怎样处理？
- 如何证明人工编辑不发出新模型请求，而不是只依赖口头约定？

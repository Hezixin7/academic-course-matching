## 在自己电脑执行

1. `npm run bootstrap`、`npm run setup`。
2. 用编辑器从 .env.example 建立 .env，填写真实密钥；运行 `npm run dev`。
3. 打开 localhost 页面，确认模型配置已读取。此时还不能证明密钥有效。
4. 上传 examples 中三份 CSV 或载入示例，运行完整 LLM 匹配。
5. 检查候选明细的四类判定、理由和两侧引用，以及模型、Prompt 版本和 usage。
6. 每个正向建议仍待人工复核；部分匹配和多个完整匹配的学分初始为 0。
7. 把一条分配减小 0.5，检查未分配和目标模块变化；输入 900 应被拦截。
8. 人工确认后调整金额，确认状态回到待复核。改模块后原 LLM 判断应显示不再适用。
9. 调整换算系数，确认不出现新的 /api/classify 请求。
10. 再次运行相同完整流程，检查 trace 的 cacheHit 和 usage，仍逐条复核。
11. 使用无效密钥重启，确认错误明确显示为待复核且不自动计分。
12. 下载 JSON / HTML，检查模型信息、校验状态、来源和人工记录。不要把真实个人报告提交到 GitHub。
13. 不填密钥时，完整模式不可用；选择仅检索预览，应没有 /api/classify 请求和自动分配。
14. 运行 `npm run eval:llm -- --split=test`，检查输出是否包含真实 providerModel、混淆矩阵和错误样例。

请在真正完成后再把对应项目标成已验收；尤其不要用测试服务响应冒充真实 LLM 推理。
